01 — WHY THIS PROJECT

Moving from traffic analysis to wireless system integration

The MAWI project focuses on understanding real backbone traffic after packets have been captured. This project extends that story into wireless systems by building a controlled 5G environment, automating how it is deployed, and testing how the system behaves under normal and faulty conditions.

The goal is not to claim a production mobile network or RF lab. It is to create a transparent virtual testbed that demonstrates 5G architecture, Linux networking, automation, test planning, log analysis, and performance measurement.

03 — PLANNED TESTS

What the first release will validate

Registration and connectivity

Verify gNB-to-core connectivity, UE registration, PDU-session establishment, assigned IP connectivity, and external traffic flow.

Performance testing

Measure throughput, latency, packet loss, and test duration using repeatable traffic scenarios.

Multi-UE load

Compare performance as multiple virtual UEs share the same environment and traffic demand increases.

Failure injection

Introduce configuration and service failures, then use logs and automated checks to isolate the likely cause.

04 — AUTOMATION PLAN

How Ansible and Python will support the lab

Ansible

  • Prepare Linux hosts and install dependencies
  • Render gNB, UE, and core configuration templates
  • Start services in the required order
  • Load scenario variables and reset the lab
  • Collect logs and test artifacts

Python

  • Check service and registration readiness
  • Run ping and iperf3 test traffic
  • Parse UE, gNB, and core logs
  • Calculate throughput, latency, and loss
  • Generate structured pass/fail reports
