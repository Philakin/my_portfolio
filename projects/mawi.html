Overview

Modern computer networks generate millions of packets within seconds, making it nearly impossible to understand network behavior by manually inspecting packet captures. While tools such as Wireshark are excellent for analyzing individual packets, they become difficult to use when working with large backbone captures containing millions of records. Network engineers instead rely on aggregated metrics, traffic statistics, and visualization platforms to identify congestion, protocol behavior, and performance issues.

This project aims to bridge that gap by building a complete network traffic analytics platform that transforms raw packet capture (PCAP) files into meaningful network-performance insights. Using the public MAWI backbone traffic dataset, the platform parses packet-level information, engineers network traffic features, and presents the results through an interactive analytics dashboard.

Rather than focusing on individual packets, the project analyzes traffic behavior over time, allowing trends such as retransmissions, protocol distribution, traffic bursts, and IP activity to be explored more efficiently.

Project Motivation

As part of my graduate studies in Telecommunications, I wanted to build a project that reflected the type of work performed by network engineers and network automation engineers in production environments.

Many networking projects focus on configuring routers or simulating small lab topologies. While valuable, they rarely demonstrate how engineers analyze real network traffic collected from operational backbone networks.

The MAWI Working Group Traffic Archive provides anonymized backbone traffic collected from production Internet infrastructure, making it an excellent dataset for studying realistic traffic behavior at scale.

The goal of this project was not simply to inspect packets, but to build an end-to-end analytics pipeline capable of:
  • Packet count
  • Average packet size
  • TCP retransmission rate
  • Protocol distribution

Packet Parsing

The first stage transforms the raw packet capture into structured data that can be analyzed programmatically. PyShark is used as the Python interface to TShark, allowing the capture to be processed packet by packet.

For each supported packet, the parser extracts:

  • Packet number
  • Capture timestamp
  • Source IP address
  • Destination IP address
  • Transport protocol
  • Packet length

The first development sample contained approximately one million packets. From this sample, 904,720 packets containing the required IP and transport information were successfully written into a structured packet-level dataset.

Packets without the expected IP-layer fields were excluded from the first parser. These remaining packets will be revisited in a separate non-IP protocol analysis stage so that protocols such as ARP, LLDP, STP, and other Ethernet-level traffic can be handled appropriately.

Feature Engineering

Inspecting nearly one million packets individually is not practical for understanding overall network behavior. To make the traffic easier to analyze, the packet-level dataset is aggregated into fixed 100-millisecond time windows.

Each time window becomes one observation containing numerical features that describe network activity during that interval.

The current one-million-packet sample spans approximately 3.12 seconds. Using 100-millisecond intervals produces 32 time windows and 17 engineered features. This resolution provides more detail than one-second aggregation while remaining compact enough for dashboard analysis.

TCP Retransmission Analysis

TCP retransmissions occur when a sender does not receive the expected acknowledgment and sends a packet again. Frequent retransmissions can be associated with packet loss, congestion, unstable paths, or other network reliability problems.

Retransmissions are identified using Wireshark and TShark analysis logic through the following field: 

tcp.analysis.retransmission

The parser identified 6,403 TCP retransmissions in the development sample. These events were stored in a separate retransmission dataset and then grouped into the same 100-millisecond windows used for the main feature table.

The project calculates both raw retransmission count and retransmission rate. The rate is more informative because it normalizes retransmissions according to the amount of TCP traffic in each window. 

retransmission_rate = retransmission_count / tcp_count

This makes it possible to compare windows fairly, even when they contain different traffic volumes.

Technical Challenges

Processing Large Packet Captures

The original MAWI capture is approximately 19 GB, which makes full-scale experimentation slow and difficult during development. A one-million-packet sample was therefore used to build and validate the initial pipeline before scaling to the complete capture.

Handling Different Packet Types

Not every packet contains IP-layer fields. The first parser focused on IP traffic because the initial analysis centered on TCP retransmissions, transport protocols, IP addresses, and packet-level performance metrics. Non-IP packets are tracked as a separate planned analysis module rather than being silently ignored.

Timestamp Processing

Some timestamps included microsecond precision while others ended exactly on a whole second. Pandas therefore required mixed timestamp parsing before the values could be grouped correctly into time windows. 

pd.to_datetime(df["Time"], format="mixed")

Selecting the Time-Window Size

Initial one-second aggregation produced only four observations because the sample covered slightly more than three seconds. The time-window size was changed to 100 milliseconds, producing 32 observations and providing more detailed temporal behavior for analysis and visualization.

Managing Large Generated Files

Packet-level CSV files and raw PCAP files can become very large. Git ignore rules were added so that the repository includes source code and smaller processed outputs without storing raw packet captures, virtual environments, or oversized intermediate files.

Final Thoughts

This project began as an exploration of a large packet capture and has developed into a modular network traffic analytics pipeline. The current system can parse real backbone traffic, identify TCP retransmissions, generate structured network-performance features, and present those results through an interactive dashboard.

The project combines concepts from computer networking, telecommunications, software engineering, and data engineering. It also demonstrates the process of moving from raw network data to a usable analytics application rather than stopping at packet inspection alone.

The current one-million-packet implementation serves as the validated prototype. The next stages will focus on improving dashboard interactivity, adding advanced traffic features, scaling to larger portions of the original capture, and evolving the application into a containerized full-stack platform with a REST API and React-based interface.
